# 요양시설 스튜디오

주간보호센터·소형 요양원용 돌봄 업무 앱. Dolbom Studio(우리 팀 업무 공간)를
**돌봄 현장** 쪽으로 옮긴 것. 쓰는 사람만 연구원에서 요양보호사로 바뀐다.

## 실행

```bash
python -m streamlit run care_studio/app.py --server.port 8533 --server.headless true
```

폰에서 음성을 쓰려면 **HTTPS** 여야 한다(브라우저가 http 에서 마이크를 안 준다):

```bash
python -m streamlit run care_studio/app.py --server.port 8533 --server.address 0.0.0.0 \
  --server.headless true \
  --server.sslCertFile care_studio/certs/cert.pem --server.sslKeyFile care_studio/certs/key.pem
```

인증서는 자체서명이라 폰에서 경고가 뜬다 — 계속 진행하면 된다. 만드는 법:

```bash
MSYS_NO_PATHCONV=1 openssl req -x509 -newkey rsa:2048 -nodes -days 825 \
  -keyout care_studio/certs/key.pem -out care_studio/certs/cert.pem \
  -subj "/CN=care-studio-local" \
  -addext "subjectAltName=IP:<이 PC IP>,IP:127.0.0.1,DNS:localhost"
```

## 근거 — 지어낸 항목이 없다

- **급여제공기록지**: 노인장기요양보험법 시행규칙 [별지 제15호서식] (개정 2019.9.27)
  원문 PDF에서 항목을 그대로 옮겼다. 목욕 소요시간·방법, 식사 종류·섭취량,
  화장실 총 횟수, 프로그램명 기재, 구역별 작성자 서명까지 서식 유의사항 반영.
- **급여제공계획서**: [별지 제11호의4서식] (개정 2021.6.30). 작성방법(뒤쪽)의
  "급여 개시 전 작성 · 충분한 설명 후 동의 · 공단 통보"를 화면에 안내로 넣었다.
- **욕구사정 9항목**: 평가매뉴얼 114쪽 '욕구사정 세부내용' 을 옮겼다.
  ⚠️ 매뉴얼은 "9개 항목"이라면서 번호는 1~8까지만 열거한다. 본문 다른 곳에
  '구강상태'가 언급돼 9번으로 넣었다. [[확인필요]]
  매뉴얼이 못박은 것: **단순 체크는 불인정, 판단 근거를 서술**해야 한다.
- **상담 필수 기재**: 상담일자·수급자명·상담직원명·상담대상자명(관계)·상담내용.
- **결과평가**: 반기별, 결과 반영해 계획서를 **30일 이내 재작성**.
- **프로그램은 셋으로 나눴다** — 평가매뉴얼이 종류마다 주기를 달리 정한다:
  신체기능(지표 24) 주 3회 · 인지기능(지표 25) 주 3회 · 사회적응(지표 26) 월 1회.
  한 대장으로 묶으면 사회적응이 신체기능 주기에 묻힌다.
- **대장·점검 12종의 주기**: 2026년 장기요양기관 재가급여(주야간보호) 평가매뉴얼.
  프로그램 주3회, 소독 분기, 소방 매월, 재난훈련 반기, 교육·건강검진 매년 등.
  ※ 배점·세부 평가기준은 매뉴얼에 "비공개"로 명시돼 있어 담지 않았다.

서비스모델 논문(JMIR Aging 투고본)의 **TO-BE 서비스 블루프린트(급여 이용 중)** 에

근력지원 · 이동지원 · 이승지원 · 배설지원 · 식사보조 · 목욕보조 · 모니터링 · 의사소통

⚠️ 논문 초록은 **10종**이라고 밝히고 있으나, 한 곳에 열거된 목록을 찾지 못했다.
위 8종은 블루프린트 도식에서 확인한 것이다. [[확인필요: 나머지 2종]]
(블루프린트에 `Play Tag (daily log)` 라는 항목이 따로 있는데 기기인지 기록 도구인지
확인하지 못해 넣지 않았다.)

## 다크 모드

사이드바의 **🌙 어두운 화면으로 / ☀️ 밝은 화면으로** 로 전환. 계정별로 기억한다
(`data/prefs.json`).

⚠️ 다크에서 **순백 글씨는 눈부시다**(18.7:1). 그렇다고 낮추면 시력 저하자가 못 읽는다.
→ 본문 `#DAD7D2` **13:1**, 보조 `#A8A49E` 7.6:1, 배경 `#121212` 로 잡았다.
⚠️ 드롭다운·달력은 body 포털이라 앱 밖에 그려진다 → `div[data-baseweb="popover"]` 를
따로 덮어야 흰 칸이 안 남는다(돌봄스튜디오에서 겪은 것).

## 색과 글씨 — 시력 저하자 기준

인스타그램 화면을 따르되 **원색을 그대로 쓰지 않았다.** 흰 배경 대비를 계산하면
셋 다 본문 기준(4.5:1) 미달이다:

```
회색 #8E8E8E 3.28:1 · 파랑 #0095F6 3.17:1 · 빨강 #ED4956 3.69:1
```

진한 쪽으로 바꿨다:

```
본문 #1A1A1A 17.4 · 보조 #595959 7.0 · 파랑 #0B5FCC 6.0 · 경고 #C62828 5.6
```

인스타 원색은 **면적이 큰 배경**(그라디언트 링·로고)에만 남겼다.

그 외: 기본 글씨 18px · 줄높이 1.65 · 버튼 높이 48px 이상 · 입력칸 46px ·
placeholder `#6E6E6E`(브라우저 기본 opacity 해제) · 테두리 `#C7C7C7`.

⚠️ 여백·정렬 CSS 는 `section[data-testid="stMain"]` 으로 한정했다.
전역으로 두면 사이드바 간격이 무너진다(돌봄스튜디오에서 두 번 겪은 함정).

## 색

인스타그램 계열 그라디언트 — `#F58529 → #DD2A7B → #8134AF → #515BD4`.
제목(h1)과 주요 버튼·사이드바 테두리에만 그라디언트를 쓰고, **본문 글씨는 진하게**
둔다. 파스텔 위에 파스텔 글씨를 얹으면 현장에서 안 읽힌다.
(Dolbom Studio 는 주황 #C4622D — 서로 다른 물건임이 한눈에 보이게.)

## 보호자 알림장

케어노트가 하는 '시설 → 보호자' 소통. 우리는 **이미 적은 기록에서 문장을 자동으로**
만든다(따로 쓰지 않게 하는 것이 요점). 📄 일지 화면에서 이용자를 고르면 나온다.

⚠️ **보내는 기능은 없다.** 문장을 만들어 주면 사람이 읽어보고 문자·카톡으로 보낸다.
자동 발송은 잘못된 내용이 그대로 나가므로 1단계에서는 만들지 않았다.

## 원칙

- **자동 확정 저장 없음.** 음성이든 화면이든 사람이 누른 뒤에만 저장된다.
- **감사 기록 분리.** 서식은 최종 상태만, 누가 언제 무엇을 음성/화면 중 무엇으로
  넣었는지는 `records` 에 따로 쌓는다.
- **데이터는 이 PC 안에만.** `care_studio/data/*.json` (git 제외).
  이용자 이름·건강 상태가 들어가므로 시연 단계에서 밖으로 내보내지 않는다.

## 한계 — 분명히 해둘 것

- **PIN 로그인은 최소 잠금**이다. 시설 안 공용PC 기준. 인터넷 공개용으로는 부족하다
  (계정·2단계 인증 필요).
- **음성은 브라우저(구글) 서버를 거친다.** 시험 단계에서는 이용자를 가명·코드로 부른다.
  크롬 계열 전용. 실제 마이크 받아쓰기는 **아직 현장 검증 전**이다.
- 여러 기기 동시 편집은 범위 밖(마지막 저장 우선).
- 공단 청구 연계·보호자 알림은 없다.
