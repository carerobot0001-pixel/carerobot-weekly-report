# 요양시설 스튜디오 — 잠시 멈춤 (2026-08-11)

과장님 지시로 시작해 1단계를 만들어 둔 상태. **당분간 중단**한다.
다시 시작할 사람(또는 나중의 나)이 이 문서만 보고 이어갈 수 있게 적는다.

## 지금 어디까지 됐나

**동작하는 앱**이다. 화면 14개, 데이터는 로컬 JSON.

```bash
python -m streamlit run care_studio/app.py --server.port 8533 --server.headless true
```

폰에서 음성까지 보려면 HTTPS 로 띄운다(브라우저가 http 에선 마이크를 안 준다):

```bash
python -m streamlit run care_studio/app.py --server.port 8533 --server.address 0.0.0.0 \
  --server.headless true \
  --server.sslCertFile care_studio/certs/cert.pem --server.sslKeyFile care_studio/certs/key.pem
```

인증서는 `certs/`(git 제외). 만료되거나 PC IP 가 바뀌면 README 의 openssl 명령으로 다시 만든다.
현재 IP 기준 주소: `https://192.168.0.10:8533` — 자체서명이라 폰에서 경고를 넘겨야 한다.

## 파일

```
care_studio/
  app.py       화면 전부 (사이드바·홈·14개 페이지)
  store.py     데이터·서식 정의·주기 계산   ← 근거가 주석으로 다 적혀 있다
  voice.py     브라우저 음성인식(Web Speech API)
  README.md    근거·한계·색 기준
  data/*.json  시연용 데이터 (git 제외)
  certs/       자체서명 인증서 (git 제외)
```

`store.py` 를 먼저 읽으면 된다. 서식 항목·평가지표 근거를 전부 주석으로 달아 뒀다.

## 검증한 것 / 안 한 것

**했다** — 서식 저장·일지 생성·월간 CSV·백업 zip·주기 경과 계산·기기 매칭·
말→초안 파싱(현장 말투 6종)·PIN 해시·다크 대비(브라우저에서 실측).

**안 했다**
- **실제 마이크 받아쓰기.** 화면과 저장 경로까지만 확인했다. 현장(또는 폰)에서 한 번 눌러봐야 한다.
- 여러 기기 동시 사용. 지금은 마지막 저장이 이긴다.
- 실제 센터에서의 사용. 시연 단계다.

## 재개하면 먼저 할 일 (순서대로)

1. **폰에서 음성 한 번 눌러보기** — 유일한 미검증 핵심 기능
2. **급여제공계획서 외 서식 확인** — 기초평가(낙상·욕창·인지) 서식은 기관 자체 양식이라
   실제 센터 것을 받아봐야 한다
3. **외부 연계 확인** — 이지케어·케어포가 엑셀·API 로 데이터를 받는지.
   **도입 성패가 여기 걸린다.** 안 되면 우리 기록을 사람이 다시 옮겨야 한다
4. 여러 기기 동시 사용(서버·DB) 검토 — 시설 도입 전 필수

## 미확인으로 남긴 것

- 욕구사정 **9번 항목**: 매뉴얼이 "9개"라면서 1~8만 열거. '구강상태'로 넣었으나 추정.
  화면에도 `※ 9번 항목은 확인 필요` 로 표시해 뒀다.
- 논문 TO-BE 로봇 **10종 중 8종만** 확인. `Play Tag (daily log)` 가 기기인지 기록 도구인지 모름.
- 케어포 자료의 **가족지지 프로그램(반기)** — 평가매뉴얼에서 확인 못 해 대장에 안 넣었다.
- 케어포 **음성 기록의 실제 수준**, 이지케어 **AI 계획서 생성 방식**.

## 시장에서의 결론 (다시 시작할 때 흔들리지 말 것)

- **청구·회계·세무는 만들지 않는다.** 이지케어 9,499곳·케어포가 공단·홈택스·4대보험과
  실시간 연동한다. 월 3만 3천원짜리와 정면으로 붙을 이유가 없다.
- **우리 자리는 돌봄로봇 연동 하나다.** 두 제품 메뉴 어디에도 기기·로봇 칸이 없다.
- 음성 기록은 케어포에, AI 서식 작성은 이지케어에 **이미 있다.** 그것만으로는 차별점이 아니다.
